## 0. 原则与边界

- 最终目标不是题库规模、学习 Day 数或投递数量，而是 **2028 届获得可接受且有长期发展空间的工作/录用机会**。地域：贵州优先，省内选择不足或不匹配时省外灵活。优先有真实客户、成熟上下游和持续经营的研发团队；公务员/事业编/央国企作为独立出口。
- 用户实际学历：本科数据科学与大数据技术080910T、**工学学士**；2028年预计硕士计算机技术085404（电子信息0854专业学位）；双非本硕。资格按岗位公告、专业目录和招录单位核实，不能凭相近学科保证可报。
- 有院校初筛风险，但没有证据说明所有单位一律拒双非。公开未标985门槛不等于企业内部无偏好。对**获得真人面试的能力**与**通过面试的能力**分别训练。
- 用户实习真实边界：参与工业机械臂分拣的**系统集成、现场联调与测试**；不能无证据地署名为YOLO/Kalman/规划/控制商业算法独立开发者，不得上传企业非公开代码、客户名录、相机标定数据、网络拓扑/地址和内部文件。
- 仓库是**公开的训练规范与匿名学习记录**；个人姓名、联系方式、完整简历、申请账号、人格结果、工作敏感数据、面试录音不应出现在公开GitHub。个人投递日志如含隐私应在本地私有文件/私有Git仓库；公开仓库仅放模板和汇总的匿名统计。
- 之前约定另一个GPT对话负责制作**最终简历文案**；**本教学对话负责岗位JD解读、技能差距、事实核验与版本规则**，并可向简历对话提供经过审核的公开素材。双方统一以事实证据为准。

## 1. 每条求职机会都走同一个六步流程

**发现JD → 资格核对 → 岗位方向/经营尽调 → 选择真实简历模板与定向表达 → 测评/笔试/面试准备 → 记录反馈与更正训练计划。**

### 岗位进入台账的门槛

只统计**可核查的真实岗位**：来源URL、发布/截止时间、适用届别、城市、岗位性质、学历及专业限制、本科与硕士学位要求、技能栈、面试/笔试阶段顺序。找不到这些字段要标**待核验**，不把历史招聘或社招当作2028应届有效名额。限制志愿数企业须确认选择最匹配岗位。

企业质量另看可查收入、产品交付、真实客户、营收结构、现金流、组织是否量产/常年交付、合同主体、是否外包或轮岗/驻场、出差加班、安全合规。单位规模或所有制不能单独作为稳定证明。

### 可投岗位池（技能交集与机会宽度兼顾）

- 机器人系统软件与工业C++、Linux/嵌入式Linux、ROS2与运动规划/机械臂应用。
- 机器视觉/工业AI工程、三维感知、相机/传感器/算法部署、测试开发。
- 通用C++/Python软件/工业软件开发、通信运营商/央国企IT研发与信息化。
- 国考/贵州省考（行测+申论+面试）、贵州事业单位（分类职测+综应等）、相关央国企/银行科技考试，严格按各类公告。
- 纯VLA/基础模型算法研究岗为竞争性冲刺，不作为唯一押注。

## 2. 一库四版：项目/简历真实素材管理

维护一份**事实证据表**，不能对每个JD创造新经历：

| 字段 | 示例形式（不代表用户已完成） |
| --- | --- |
| 项目与本人角色 | 「在某视觉分拣项目中参与现场系统联调/测试」 |
| 本人直接完成的动作 | 配置、复现、定位、写代码、部署、建测试用例（仅填已证实） |
| 技术依据与原始证据 | 个人公开原创Git commit、日志、测试报告、录像链接（不含企业内部材料） |
| 可证实的结果 | 通过的测试、实际耗时/误差与测量口径；无法量化则不造数字 |
| 能回答的追问 | 为什么选方案、错误如何定位、怎么验证修复、失败案例 |
| 不可声明/保密边界 | 第三方算法版权、公司商业源码与数据、未知“成功率XX%” |

从此事实表派生**四个基准版本**，根据真实JD有选择地变动技能顺序、经历顺序和描述角度：

| 版本 | 面向岗位 | 简历优先表达 | 技术准备重点 |
| --- | --- | --- | --- |
| A 机器人系统软件 | ROS2/C++/Linux/机械臂软件 | MoveIt2规划vs执行、controller/action、系统调试与状态机（仅陈述实际完成部分） | C++、DDS/QoS、TF2/IK、控制器、日志与故障诊断 |
| B 工业视觉与AI工程 | 图像/3D视觉/机器视觉/端侧推理 | RGB-D、标定、坐标变换、检测/抓取系统应用中的**本人实际工作** | OpenCV、相机模型、几何、数据、推理部署、时延 |
| C 通用软件/工业软件 | C++/Python/测试开发/嵌入式Linux | 可运行代码、自动化测试、异常处理、通信、性能 | DSA、Linux、OS、网络、C++工程规范 |
| D 央国企/运营商/银行科技 | 信息化/产数/软件/技术研发 | 计算机相关本科和专业硕士、真实系统集成与问题定位、协作和交付经验 | 综合测评、编程/计算机基础、情景及岗位专门测试 |

“包装”仅指**准确地组织真实证据、适当匹配岗位语言**，**不允许**虚构技术实现、伪造实习产出、夸大个人责任、添加未掌握的JD关键词。不把纯驻场支持写成“独立研发控制器”。

### 单个JD的10分钟定向检查

1. 拆出 **硬性条件**（届别/学历/专业/城市/身份）+ 3–5项**核心技术** + 具体业务场景。
2. 从 A/B/C/D 选最接近的版本；只用证据表中已有的真实内容，把最相关的技能与经历排前面。
3. 对每个声称的核心技能准备一个**面试官可追问并亲自证明**的案例；没做过则标为「学习目标」，**不要先塞简历**。
4. 对比JD列出差距（如C++多线程/端侧部署/视觉标定）并映射到机器人Day课程或1题面试训练。
5. 保存匿名JD与版本对应关系；完整个人简历由单独简历对话维护，公开仓库只存规范和非敏感素材。

## 3. 招聘漏斗：哪些环节最影响概率？

`公开有效JD数 → 符合硬性资格数 → 实际投递数 → 测评邀请数 → 笔试邀请数 → 真人技术面数 → 复试数 → offer数`

- **测评/笔试顺序视公司而定**：部分先测评后评估简历（如小米2027流程），部分有后置简历复筛；不能把行测邮件等同于通过学校筛选，也不能把未回复等同于拒绝。
- 投递台账需存投递日期、JD及适用届别、职位匹配版本、测试阶段及日期、真实面试邀请/拒信状态、渠道/岗位类型；个人姓名、内部测评分数不进公开仓库。
- 每周看的是**资格符合岗位数、邀请率及各阶段真实转化**，不是从论坛样本计算“个人成功概率”。仅用已过合理处理期的真实投递作为分母，尚在流程中单独统计。
- 若多次“收到测评却没真人技术面”，逐项检查该公司是**先测后筛**还是**先筛后测**、测评分数/用时、岗位HC变化、技术匹配、简历证据和投递时点。
- 少量个人样本不能统计学校歧视发生率，但高质量匹配岗位长期0面试可触发策略调整（岗位池、简历、实习/内推途径）；不把增加刷题量当唯一解法。

## 4. 教学与备考实施节奏

**原则：主课与求职训练互相增益，工作日额外约20–35分钟（建议，不强制），不把每日任务数量当用户实际已完成数量。**

| 节奏 | 输出与检查 |
| --- | --- |
| 机器人主课每次 | 继续Day进度，针对当前真实代码只插入**一个**面试问答或可验证的小实验；真机仿真边界分明 |
| 每日能力题 | 行测/企业认知两道**原创储备**，用户优先答一题；滚动训练言语、数量、判断、图形、资料 |
| 每日技术 | 对照最新可信JD/一手面经抽一题C++/Linux/ROS2/视觉/DSA/控制；理解+小验证，再记录 |
| 企业测评/行为 | 周内适量练真实情景分析；职业性格测评遵循诚实作答，不整理伪造人设答案 |
| 每周公考 | 至少**一题申论**归纳/对策/应用文或论证写作，循序渐进；行测需补政治理论/常识 |
| 每周事业编 | **一次职测+综应**分类训练，按贵州岗位是A还是C等类别标注，不能和国考申论混写 |
| 每两周 | 一道公务员情境/结构化面试题，侧重有事实依据的行政管理与沟通流程 |
| 每周机会回顾 | 调查一到数个目标JD及业务实际落地情况；**尚无个人投递时不能编造转化率**；复盘需调整的简历版本或技术问题 |
| 每月 | 15–45分钟限时测评/机考基线、申论批改、真实项目可讲解成果、各类岗位覆盖与招聘进展，更新下一月优先级 |

2026-10至2027上半年重在**技术与基础题、简历素材证据、实习获取**；2027下半年依真实秋招/2028国考招聘公告加大笔试与申论模拟。错题按「概念不会、计算/审题失误、答题慢、语言表达不足、项目证据不足」分别诊断，不把不同原因一锅端。
