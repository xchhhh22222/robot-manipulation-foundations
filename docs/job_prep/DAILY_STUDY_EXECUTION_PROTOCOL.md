# 日常执行协议｜行测20题 + 项目/求职真实推进（2026-10-10修订）

> 本协议按用户2026-10-10的明确修订建立，**取代旧文本“每天只做一道题、总计20–35分钟”作为日总上限的规则**；仍坚持事实驱动、逐题反馈、及时复盘、项目和求职双轨推进。跨聊天先读本协议、LEARNING_STATE和最新daily。

## 一、每日时间与两条任务主线

| 任务 | 日投入 | 目标及完成证据 |
|---|---|---|
| 行测/企业综合测评共通能力 | **每天60–120分钟** | **目标约20题**（通常15–25题，按难度与精力浮动），记录真实作答；到时间即止 |
| ROS2/项目 **或** 求职行动 | **另留15–30分钟**，可随现实工作弹性调整 | 至少完成一项可核验动作；未执行填PENDING_USER而非DONE |
| 申论、贵州事业综应、技术面 | 每周另排专项 | 每周至少一张申论卡和一张贵州事业职测+综应卡、持续技术实践，不让行测挤占项目 |

行测1–2小时是行测本身预算，不是所有学习的总时长；项目/求职动作至少一项，不要求两项每天都做。若当天真实投递/面试/ROS2排障占用了大量时间，适当少刷题，禁止为凑够20题导致长达八小时的无限测试。

## 二、默认20题分配（可据证据动态调整）

- 言语理解5题：主旨、细节、逻辑填空、语句衔接等轮换。
- 判断推理5题：逻辑、定义、类比、图形与因果论证轮换。
- 资料分析5题：一份材料多问，增长率、平均数、比重、贡献率等。
- 数量关系3题：应用题、工程、比例、概率等逐步推进。
- 常识/政治理论2题：结合公开考试大纲，时效敏感内容需核实。

以上共20题，含2–4道到期间隔复习题，不是20道同一个错点的变式。若资料题复杂，15–18题达成当天时间预算亦算正常；申论、综应和技术题另记，不虚算进20题。题目标原创非真题。

## 三、交互与时间封顶：默认四组×五题

1. 每次开场展示当天题型配比、60–120分钟时间预算、到期复习的最多2个重点，以及**项目/求职一项明确动作**。
2. 默认每次发布**一组5题**，用户交回这5题后对**每道题**逐项批改：正确题1行要点，错误题简短按事实→根因假设→一个调整→验证条件反馈；用户要求真正一题一反馈时可逐题呈现，但不能把每题都写成数屏长课。
3. 答案不提前公布；每5题给短进度：实际已答/正确/待复习/剩余时间。每个同一错误允许**最多一题当场纠错**，还未会就转T+1/T+7，不能R1、R2、R3无限循环。
4. 达到约20题或当天时间上限就宣布行测完成。用户说累、需要停、或者已经超时，则立即结课，不强行出下一题。
5. 收尾记录真实答题数、正确数、限时用时（缺证据NOT_MEASURED）；项目/求职动作实际证据（或阻塞）；下次到期复习与下次开始点。

建议时间结构：约10分钟安排+40–75分钟限时答题+10–25分钟批改/复习，约60–110分钟。题量是目标，时间盒和长期坚持优先。避免历史一次对话超过8小时仍无止境测试的错误。

## 四、每天至少一个真实项目或求职成果

- 项目日：延续ROS2/MoveIt2 Day28的真实状态，只推进一项命令、最小调试或代码/运行证据；要用户给出输出、日志或Git SHA才记DONE。不要把WSL本地改动当成GitHub已同步，不上传实习商业材料。
- 求职日：核实1条公开JD/公告的届别、专业（硕士085404）、学历、地点和硬限制；或对既有JD完成1项真实简历证据映射/技术关键词调查/投递准备。没有实际投递数据用NOT_MEASURED，不编造转化率。
- 地域分轨：公务员/事业编/央国企/运营商/银行贵州优先、省外合适机会补充；机器人、工业C++、机器视觉、AI/具身研发岗位优先一线新一线城市。历史2027届JD不得冒称当前2028届岗位。
- 仅提出建议而用户尚未执行，记PENDING_USER，不等于完成。项目/求职可以按工作强度轮换，但不能一周只刷题没有真实技能或职位推进。
