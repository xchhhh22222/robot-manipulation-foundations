## 4. 建议的职业定位（讨论版）

**推荐主线：机器人系统软件 / Manipulation 系统研发。**

**差异化第二主线：视觉引导抓取、跟踪/预测及端侧模型部署。**

**中长期上限：Robot Learning / VLA 后训练、机器人策略推理与评测。**

原因：
1. 当前已有 ROS2、MoveIt2、IK、Planning Scene、Pick & Place 的独立仿真基础，以及真实机械臂项目联调体验。
2. 企业多类实际 JD 都有 C++/Linux/ROS2/通信/调试/多模块协同或端侧推理的交集。
3. 单纯从零转 STM32 驱动会使既有 manipulation 积累暂时断层；单冲 VLA 核心研究需补大量训练/论文工作，求职风险高。
4. 最有辨识度的作品可以是**独立复现的视觉移动零件抓取系统**，将安全边界、坐标标定、运动时序、端侧运行和失败分析结合起来。

## 5. 课程调整建议（尚未最终决定）

原来 `ROS2 → MoveIt2 → IK → TF/Camera → MuJoCo → 数据/评测 → LeRobot/ACT → Diffusion → VLA` 的**主干继续**，但插入并前置两条横向能力：

- **C++ / Linux 系统工程**：每周一到两个小任务，涵盖 ROS2 rclcpp、callback/executor、通信 QoS、线程/状态机、日志、性能 profiling；不要求立刻重写整个 Python Demo。
- **视觉感知到抓取与可测评**：TF2/SE(3) 和相机坐标/手眼标定前移；尽快开始可合成数据的移动目标、时间戳、跟踪/延迟测量和 failure taxonomy。
- **端侧模型部署**：在初步视觉链路验证后开展一次小模型 ONNX→TensorRT/ONNX Runtime→ROS2 推理节点实验；关注 latency、FPS、资源占用，而非把“运行大 VLA”作为短期门槛。
- **Robot Learning 保留**：用公开/自生成 episodes 进入 LeRobot、ACT、Diffusion、LIBERO/VLA，不放弃学术能力与论文研究。
